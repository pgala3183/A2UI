# Video script · Part 1 · A2UI (about 20 min)

## 0:00 What A2UI is (2 min)

**Screen:** `codelabs/01_a2ui/README.md`, the four envelopes.
**Say:** "A2UI sends UI as a stream of JSON messages. createSurface, updateComponents with a flat list of components joined by ids, updateDataModel with a JSON Pointer, deleteSurface. Structure and data are separate messages. The client answers with an action envelope."
**Open:** `_shared/surface.mjs` `apply()`. "Components into a Map, data through a pointer."

## 2:00 Chapter 1 · Static: fixed templates, streaming data (4 min)

**Run:** `cd codelabs/01_a2ui/01_static`, `python demo.py`. Point at "bytes by message type".
**Run:** `python server.py`, open http://127.0.0.1:8101, click Run. Point at the wire: one updateComponents, then updateDataModel every tick. Click Refresh.
**Code (README order):** `agent.py` `STATION_STATUS` (bindings, no data) → `TOOLS` (enum: the model can only select) → `server.py` `show()` (structure once, then data) → `action()` (the app answers; granular pointers) → `_shared/surface.mjs` `action()` (context resolved at click time).
**Test:** `python -m pytest -q`; name `test_structure_is_sent_once_then_only_data`.
**Takeaway:** "Static A2UI: the model selects; the layout is sent once; data streams."

## 6:00 Chapter 2 · Declarative: the model writes the components (5 min)

**Run:** `$env:GENUI_DELAY = "0.05"`, `python server.py` in `02_declarative`, http://127.0.0.1:8102, Run. Point at the skeletons, then the note with attempt 1's error, the deleteSurface, attempt 2.
Type a bike number and an issue, tick the checkbox, Send. Point at the action envelope's context and the server's answer.
**Code:** `_shared/a2ui.py` `Catalog.prompt()` → `agent.py` sections and the deliberate `Dropdown` → `server.py` `generate()` (validate each line, withdraw, correction turn) → `_shared/render.mjs` skeletons and two-way binding → `check_report()`.
**Takeaway:** "Prompt-first generation needs a validator, and validation errors are the next prompt."

## 11:00 Chapter 3 · Open-ended: a custom catalog with one HtmlFrame (4 min)

**Run:** `03_open_ended`, `python server.py`, http://127.0.0.1:8103. Wait for "Peak pricing". Move the slider, Book.
**Show:** DevTools → the iframe has `sandbox="allow-scripts"`; the CSP meta tag in its srcdoc.
**Code:** `_shared/htmlframe.py` (one-component catalog + policy) → `common/genui_common/sandbox.py` policy → `_shared/htmlframe.mjs` (FrameHost slot) → `server.py` peak pricing push and `ride_cost` (the server's price).
**Takeaway:** "A2UI carries open-ended UI by swapping the catalog. The data model still drives it."

## 15:00 Chapter 4 · Mixed: Basic Catalog + one HtmlFrame (4 min)

**Run:** `04_mixed`, http://127.0.0.1:8104. In the simulator: 8 bikes, Ferry Building → Mission & 16th, Apply. Point at the caption above (catalog) changing, and the simulator keeping its selection. Click Refresh numbers.
**Code:** `_shared/htmlframe.py` `MIXED_CATALOG` → the prompt rule in `agent.py` → "at most one HtmlFrame" in `server.py` → actions bound to their source component → `common/web/morph.mjs` (frames are opaque).
**Takeaway:** "Catalog by default, one generated region, one data model for both."

## 19:00 Wrap-up (1 min)

`python run_all.py codelabs/01_a2ui` (all green). "Static to mixed, A2UI's answer is the same: a flat map plus a data model, and the catalog decides what is allowed."
